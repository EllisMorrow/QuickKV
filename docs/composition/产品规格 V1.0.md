# QuickKV · 组合输入｜最终产品规格 V1.0

通用公开基线。第 0 节记录初审阶段的授权边界，后续实施按已审核方案和开发授权推进。

## 0. 任务定位与执行约束

- 本规格定义 QuickKV 组合输入的产品行为。所有场景和样例使用独立构造的虚构数据。
- 项目：
  - QuickKV：https://github.com/EllisMorrow/QuickKV
- 本次任务是在现有 QuickKV 中新增一种名为「组合输入」的输入模式，而不是创建另一个独立软件，也不是开发特定笔记应用的插件。
- 本规格是产品需求基线。之前讨论中的旧原型、旧名称及旧交互方式若与本规格冲突，以本规格为准。
- 当前阶段仅要求理解需求、审查现有源码、研究技术路线和提交工程设计方案。
  - 暂时不要修改生产代码。
  - 不要擅自删除、重构或改变现有功能。
  - 不要在工程方案获得确认之前直接开始全面实现。
- 产品需求与技术实现应当分开。
  - 产品行为以本规格为准。
  - 具体文件划分、Qt 组件选型、序列化方案、存储格式和技术架构由工程研究决定。
  - 发现需求冲突、性能问题或技术限制时，应说明问题及替代方案，不要静默简化需求。

## 1. 产品目标

- 为用户建立一种高效率、高一致性、高自由度的通用结构化文本录入能力。
- 典型使用场景包括：
  - 项目任务管理，在较短时间内完成多维观察、判断、预测和记录。
  - 日常事务管理、时间运用和流程复盘。
  - 阅读研究、知识整理及未来其他尚未形成稳定结构的研究主题。
- 核心价值：
  - 将部分主动回忆、词汇组织和重复打字任务转化为识别与选择。
  - 降低用户在精神状态不佳或时间紧张时的认知负担。
  - 提高观察框架、表达词汇及研究数据的一致性。
  - 保留自由思考、自然语言及不断变化的结构。
  - 为后续共性、差异性、条件敏感性及其他统计分析积累可移植的高质量数据。
- 核心产品原则：
  - 配置时足够强大，使用时足够简单。
  - 选择应尽可能比手动打字更快。
  - 不强制填写预设结构，不限制用户自由表达。
  - 成熟的知识可以快速调用，未知的知识可以随时补充。
  - 尽量保持正文如普通 Markdown 笔记一样自然、轻盈。
  - 长期积累的词库、组合配置、观察框架及模板必须可安全保存、备份和迁移。
  - 不依赖任何特定笔记软件或私有笔记格式。

## 2. 与现有 QuickKV 的融合

- 在 QuickKV 现有主弹窗标题栏中，于「连续联想」左侧新增「组合输入」按钮。
- 点击后在原有 QuickKV 主弹窗内部切换输入模式，不创建新的独立主窗口。
- QuickKV 最终具有三种输入模式：
  - 普通搜索：保持现有功能。
  - 连续联想：保持现有功能。
  - 组合输入：新增功能。
- 应尽可能复用现有基础设施：
  - 全局热键和窗口唤出。
  - 窗口置顶、位置、尺寸、主题、字体与显示设置。
  - 多 Markdown 词库加载、监听、检索和缓存。
  - 拼音、拼音首字母、关键词、别名及已有词条搜索能力。
  - 动态变量与模板渲染能力。
  - 剪贴板、目标窗口管理、安全落字与失败恢复机制。
- 不得因为新增第三种模式而破坏普通搜索及连续联想。
- 应检查现有模式状态、快捷键、焦点管理、控制器及落字流程，避免将第三种模式硬塞进只适用于两种模式的布尔判断。
- 每种草稿型输入模式独立保留未完成的草稿。
- 切换模式不丢失草稿。
- 组合输入本身也应能调用现有的词库检索及连续联想能力。
- 原生 QuickKV 的具体版本、架构及已有实现，以当前本地仓库实际源码为准。

## 3. 组合输入主界面

- 界面整体保持 QuickKV 现有风格，简洁、紧凑、低干扰。
- 标题栏：
  - QuickKV。
  - 组合输入。
  - 连续联想。
  - 原有窗口关闭等控件。
- 组合输入模式的轻量工具区域：
  - 当前输入模块及切换入口。
  - 模板调用入口。
  - 回载编辑入口。
  - 悬浮响应开关。
  - 更多操作菜单。
  - 必要的高频编辑功能。
- 主体为可自由编辑的多层级大纲正文。
- 底部可提供复制、整段落字、必要状态提示及可折叠的 Markdown 输出预览。
- 不应常驻显示复杂属性面板、大量设置按钮、所有词组或大面积检查清单。
- 低频局部操作优先通过右键菜单及浮窗实现。
- 高频操作可以通过鼠标、光标及快捷键直接完成。
- 工具栏是否固定、具体图标及布局细节可以根据现有 QuickKV 风格进行合理优化。

## 4. 自由大纲编辑器

- 大纲正文是核心编辑区域，不是固定表单，不是只能填值的模板。
- 必须支持：
  - 正常文字输入、中文输入法、连续打字。
  - 任意位置移动光标、选中文字、剪切、复制、粘贴、删除。
  - 撤销及重做。
  - 新建根级、父级、同级及子级节点。
  - 任意合理层级的缩进及反缩进。
  - 子大纲折叠及展开。
  - 分支复制、移动及删除。
  - 任意位置新增、删除或替换组合词元。
  - 普通文字与组合词元之间双向转换。
- 一行内容可以自由混合：
  - 一个或多个键值组。
  - 同一个键对应的多个值。
  - 任意位置的自然语言注释。
  - 普通标点、数字和 Markdown 语法。
  - 一个或多个组合词元。
- 示例：

  `- 任务：高-大型+开发+进行中、开发+待审核，时间：0917，需要补开变更单，评分：3.14`

- 键和值均可以是普通文字，也可以是组合词元。
- 冒号、顿号、逗号、空格、句号等均可直接用键盘输入。
- 不要求通过专门的按钮插入普通标点。
- 不限制同一行只能存在一个键值组。
- 自然语言可以插入任意两个键值组之间，也可以出现在行首或行尾。
- 输出为正常 Markdown 或纯文本，不携带内部组件标记、隐藏字符或专有格式。
- 对于回载的原始内容，不应强制重新格式化缩进、列表符号、标点或空行。

## 5. 最小交互单位：组合词元

### 5.1 基本概念

- 一个组合词元由以下三部分构成：
  - 零个或多个前缀。
  - 一个主词。
  - 零个或多个后缀。
- 前缀、主词、后缀都可以通过独立关联词组进行选择。
- 一个词元的前缀、主词、后缀属于同一个完整的可编辑实例。

### 5.2 最终输出规则

- 主词与前缀区域之间使用英文 `+`。
- 主词与后缀区域之间使用英文 `+`。
- 同侧多个前缀或后缀之间使用英文 `-`。
- 空缺的前后缀不输出多余连接符。
- 例子：
  - `开发`
  - `高+开发`
  - `高-大型-技术部+开发`
  - `开发+进行中`
  - `开发+进行中-待审核`
  - `高-大型+开发+进行中-待审核`
  - `西区-线上+工作坊`
  - `设计组-0917+评审`
- `+` 和 `-` 为当前确定的默认序列化格式。
- 内部必须独立保存主词、所属主词组、前缀及后缀结构，不能只保存拼接字符串。
- 单个 `+` 的文本可能存在前缀或后缀方向歧义；词汇本身也可能包含连接符，不能假定纯文本总能唯一拆解。
- 外部分析工具未来如何拆解、统计这些组合词元，不属于本次开发范围。只需保证输出开放、清晰、可衔接。

### 5.3 正常与激活状态

- 非激活状态：
  - 组合词元看起来就是普通文字。
  - 不常驻显示边框、色块、空前缀或空后缀入口。
  - 不显示类似「+前 开发 后+」的永久控件。
- 激活状态：
  - 光标进入或邻近词元、鼠标点击、开启悬浮响应后悬浮词元，可以显示三向操作入口。
  - 前缀入口、主词入口、后缀入口分别进入相应的选择面板。
  - 当前已有的修饰词可作为相应入口的一部分。
- 离开或结束编辑后恢复普通文字显示。
- 尽可能使用不改变正文布局的局部装饰或浮层，避免激活时文字跳动、换行或光标错位。
- 词元不是不能编辑的永久标签；用户应能够将其还原为普通文字。
- 手动修改词元内部文字时，需要有明确的更新或解除词元关联机制，不能留下错误的内部结构。

## 6. 独立关联词组及组合规则

### 6.1 独立词组

- 词组是独立、可命名、可复用的数据单位。
- 每个词组包含一系列词汇或多级分类。
- 支持：
  - 新建、重命名、检索、复制、排序及删除词组。
  - 在词组内新增、编辑、删除、排序词汇。
  - 新建分类。
  - 在分类内继续建立子分类及词汇。
  - 合理数量的任意层级分类，不人为限制只能一级或两级。
- 分类用于组织选项，不默认作为最终输出值。
- 例如：
  - 资料来源
    - 书籍
      - 技术读物
        - 编程入门
        - 数据建模
      - 人文读物
        - 艺术史
    - 音频
      - 课程录音
      - 访谈
- 「编程入门」位于「技术读物」下，「音频」是与「书籍」并列的分类。
- 同一词组可以被多个主词组、多个模块及多个前后缀位置引用。
- 一个词汇可以属于多个不同词组。

### 6.2 主词组是组合规则的归属单位

- 前后缀规则不应重复绑定到每一个单独主词。
- 主词组定义：
  - 该组包含哪些主词。
  - 可以引用哪些前缀组。
  - 可以引用哪些后缀组。
  - 各前后缀组的顺序。
- 例如：
  - 主词组：任务类型。
    - 主词：设计、开发、测试、审核。
    - 前缀组：优先级、任务规模、所属部门。
    - 后缀组：完成状态、审核状态。
  - 主词组：活动形式。
    - 主词：工作坊、座谈会、讲座。
    - 前缀组：区域、执行方式、时间戳。
    - 后缀组：报名状态。
- 同组替换主词时，保留当前已选择的前后缀。
- 跨组替换主词时，切换到新主词组的组合规则。
  - 不应将不匹配的修饰词错误地带入新组。
  - 存在修饰词丢失风险时，应提供明确提示或可撤销的处理方式。
  - 仅浏览其他组时，不立即修改当前正文。
- 新插入的词元继承其主词组的当前配置。
- 同一个主词若属于多个组，应能明确选择使用哪个组的组合配置。
- 不同词元实例共享配置，但选择结果相互独立。
- 修改共享词组或默认规则不得静默改写历史记录及其他已经录入的词元实例。
- 应明确区分共享组内选项排序、主词组的默认引用顺序、当前词元已经输出的组合顺序。

### 6.3 多组组合

- 前缀及后缀可以包含任意多个独立选择组。
- 每组通常选择一个值，允许不选。
- 例如：
  - 优先级：高、中、低。
  - 任务规模：大型、中型、小型。
  - 所属部门：技术部、设计部、资料部。
  - 完成状态：待开始、进行中、已完成。
  - 审核状态：待审核、已审核。
- 多个组是横向组合关系；组内多级分类是纵向组织关系。
- 两种关系不可混淆。
- 用户无需逐级完成所有组才能退出面板。

## 7. 三向词元浮窗

### 7.1 日常使用状态

- 激活词元后，显示前缀、主词、后缀三个入口。
- 前缀面板：
  - 同时呈现多个已配置前缀组。
  - 组名和选项排列紧凑。
  - 点击选项立即更新当前词元。
  - 再次点击已选修饰词可取消，或提供明确清除操作。
- 后缀面板采用完全一致的交互机制。
- 主词面板：
  - 显示当前主词组。
  - 可检索、浏览及切换其他主词组。
  - 可在组内检索或选择主词。
  - 允许输入临时主词。
- 高频选项尽可能直接平铺，不要求反复进入多层下拉菜单。
- 超过5个组时才将其余组向下折叠。
  - 鼠标悬浮到展开入口时立即展开。
  - 点击也可以展开。
  - 展开后保持稳定，不能鼠标稍微离开就立即收缩。
- 超长内容使用浮窗内部滚动。
- 实时组合结果应保持可见。
- 选择即时生效，不要求每次选择都点击确认按钮。
- 浮窗应支持在屏幕边缘自动选择合适方向和位置。

### 7.2 配置状态

- 同一个浮窗内提供「配置」入口。
- 配置状态采用左侧词组导航、右侧当前词组编辑的方式。
- 不将所有词组的完整配置同时纵向展开。
- 左侧：
  - 当前引用组列表。
  - 拖动排序。
  - 新建组。
  - 引用已有组。
  - 解除引用。
- 引用已有组：
  - 保留下拉浏览能力。
  - 同时支持检索。
  - 尽可能复用 QuickKV 的检索习惯及能力。
  - 防止误重复引用。
- 右侧：
  - 当前词组的名称、词汇与分类。
  - 新增词汇。
  - 新增分类。
  - 编辑、删除、排序。
  - 进入分类及返回上一级。
  - 查询或引用已有词库中的词汇。
  - 可选词汇说明和判断标准。
  - 根据词组类型显示相关数值或动态格式设置。
- 配置区设置最大合理高度，内部滚动。
- 无须打开另一个庞大的独立设置窗口完成常见词组调整。

### 7.3 拖动排序

- 配置和非配置状态均支持鼠标拖动：
  - 调整词组顺序。
  - 调整组内词汇顺序。
  - 调整同级分类位置。
- 组内排序只改变选项的展示顺序。
- 调整前后缀组顺序时，当前词元组合顺序可以随之调整。
- 共享配置的改变范围应清楚，不能意外修改其他历史实例。
- 单击负责选择，拖动负责排序，悬浮负责展开。
- 拖动期间暂停悬浮切换，避免误操作。
- 支持撤销及必要的拖动位置提示。

### 7.4 悬浮响应开关

- 主界面提供「悬浮响应」开关。
- 建议初次默认关闭，后续记忆用户选择。
- 关闭时：
  - 鼠标经过词元不主动弹窗。
  - 点击或键盘操作仍可打开浮窗。
- 开启时：
  - 鼠标悬浮词元及相应入口即可快速响应。
- 无论开关状态如何，已打开面板内的「展开其他组」都支持立即悬浮展开。
- 点击浮窗或正在配置时锁定当前浮窗，避免经过其他词元时意外切换。
- 鼠标从词元移动至浮窗时，不应意外关闭。
- 中文输入法组词、文字选区操作、拖动、右键菜单打开期间，暂停自动悬浮响应。
- Esc 关闭后，在鼠标离开当前词元前不应立即重新弹出。

## 8. 多种词组类型

### 8.1 普通词组

- 来源于现有 Markdown 词库或用户新增词汇。
- 支持分类、检索、选择及临时文字。

### 8.2 数值组

- 适用于完成比例、评分、预计耗时、次数和正负差额等。
- 可配置：
  - 最小值、最大值。
  - 步长。
  - 单位。
  - 常用值。
- 常用值直接点击选择。
- 支持手动输入合理的精度与数值。
- 滑杆可作为辅助方式，但不强制使用。
- 不能默认填入 75% 等未经用户判断的观察值。

### 8.3 动态词组：时间戳

- 默认内置一个名称为「时间戳」的动态词组。
- 与优先级、任务规模等普通组平级。
- 可被任意主词组引用为前缀或后缀，也可直接作为主词组使用。
- 默认包含以下常见格式：
  - 14位时间戳：yyyyMMddHHmmss。
  - 4位时间：HHmm，24小时制。
  - 8位日期：yyyyMMdd。
  - 6位时间：HHmmss。
  - 标准日期：yyyy-MM-dd。
  - 标准时间：HH:mm。
  - 带秒时间：HH:mm:ss。
  - 完整日期时间：yyyy-MM-dd HH:mm:ss。
  - 星期。
  - 年月：yyyyMM。
- 优先排列14位、4位和8位格式。
- 日常选择界面只显示实际动态值，例如：
  - `20310408091753`
  - `0917`
  - `20310408`
- 不要左边显示格式名称、右边显示时间值的双列样式。
- 格式名称可通过鼠标悬浮说明查看。
- 面板打开期间以本机系统时间实时更新。
- 点击选项的瞬间重新计算该值，并立即将其固化为静态文字。
- 输出、保存草稿、回载、重新编辑历史记录时不得自动刷新原时间。
- 用户可增删时间格式并调整排列顺序。
- 尽量复用 QuickKV 已有动态模板渲染机制。
- 动态时间值不进入普通 Markdown 词库，不产生大量固定时间条目。

## 9. 多输入模块

- 组合输入内部支持多个独立输入模块，例如：
  - 项目管理。
  - 阅读学习。
  - 日常事务。
  - 用户自定义模块。
- 模块通过轻量下拉入口快捷切换，可检索。
- 支持新增、重命名、复制、排序、删除和快速选择模块。
- 可配置高频模块的局部快捷键，不强制占用大量全局热键。
- 各模块独立保存：
  - 当前草稿。
  - 模板。
  - 常用组合配置及相关词组范围。
  - 观察框架。
  - 光标及必要编辑状态。
- 所有模块共享基础词库及可复用词组。
- 切换模块不丢失草稿，不重复加载全部词库。
- 默认记忆上次使用的模块。
- 不为每个模块创建一个新的独立程序窗口。
- 删除模块涉及未提交草稿时必须有适当的数据保护。

## 10. 局部大纲模板

- 用户可以从真实编辑的大纲中选择一个节点及其分支，直接保存为可复用模板。
- 模板支持名称、检索、修改、复制、排序及删除。
- 可以选择：
  - 保留全部具体值。
  - 清空需要重新观察的值。
  - 有选择地保留稳定值并清空其他值。
- 清空值后，内部仍保留对应的主词组、前后缀配置及输入位置。
- 模板不只是普通文本复制，还应能保留可编辑结构及词元关联。
- 模板支持自然语言占位及动态变量。
- 调用模板后可继续自由修改。
- 未填写的模板占位默认不输出为真实观察数据；同时不能因此破坏有意义的父子结构或回载原文。
- 修改模板不自动改变已经生成的笔记。
- 允许快速复制当前实际分支以开始一次新的分析，但对旧观察值是否保留，应由用户明确选择。
- 避免上一次任务的实际判断、结果或进度被误认为下一次任务的新观察。

## 11. 观察维度提示

- 观察维度是辅助用户调用认知框架的功能，不是强制表单，也不是分析质量评分。
- 可以从现有大纲模板提取维度，或者手动建立、修改、删除及排序。
- 每个模块或局部分析框架可以拥有不同的观察维度。
- 每个分析父节点独立计算，不能将多个任务节点中的记录混在一起。
- 支持普通键及父子路径，例如：
  - 任务目标。
  - 进度。
  - 依赖。
  - 依赖 → 负责人。
  - 风险。
  - 结果。
- 自动根据实际正文判断相关维度是否已有非空记录。
- 不应仅因为键名存在而判断已完成。
- 不应将子级独立分析中的记录错误归入上一级分析。
- 区分四种状态：
  - 已记录。
  - 待记录。
  - 无法判断。
  - 不适用。
- 已记录由正文实际内容自动更新。
- 无法判断、不适用可以由用户主动选择。
- 不将没有记录误认为不存在。
- 删除某维度的正文后应重新更新状态。
- 观察状态应与稳定的节点身份关联，不能因为插入一行或调整顺序而串到其他节点。
- 默认视觉轻量：
  - 在对应父节点旁显示淡色小图标及类似 `4/7` 的提示。
  - 点击或按需悬浮后展开详细列表。
  - 不显示强制警告、大面积检查清单或占据正文空间的进度区域。
- 点击待记录维度时，可以快速跳到已有位置，或在正确的父子层级建立对应的输入项并开始选择。
- 观察提示与实际正文双向联动，不维护两份独立的观察记录。
- 可全局关闭、按模块关闭或按单个分析节点关闭。
- 观察提示状态本身默认不输出到笔记，除非用户主动记录。
- 不适用、无法判断如何纳入显示计数，应保持明确且不误导用户。

## 12. 词汇判断标准

- 允许为重要词汇设置可选定义、判断标准、说明及反例。
- 例如：
  - 「已完成」需要具备的交付记录。
  - 「待审核」适用的条件。
  - 「待开始」和「因依赖受阻」的区别。
- 平时不强制显示。
- 用户按需悬浮或查看说明。
- 帮助用户提高判断标准的一致性，而不仅仅是使用同一个词汇。
- 修改判断标准不自动修改历史正文。

## 13. 回载编辑（核心功能）

### 13.1 统一编辑器

- 回载编辑不是另一套编辑模式，也不建立独立的简化编辑器。
- 新建、模板调用、外部选中回载、主动粘贴都是同一个组合输入编辑器的内容来源。
- 回载后的内容拥有与原始组合输入完全相同的大纲、词元、文字编辑及词组选择能力。

### 13.2 两种回载方式

- 外部软件选中回载：
  - 用户在另一个应用中选择一段内容。
  - 通过可配置的快捷键或操作，将选区文本载入组合输入。
- 主动粘贴：
  - 在组合输入编辑器中直接 Ctrl+V。
  - 或将剪贴板内容打开为独立回载草稿。
- 不自动覆盖尚未完成的模块草稿。
- 建议使用独立临时编辑会话，继承当前模块的配置。
- 不应每次回载都永久创建一个新输入模块。
- 普通粘贴与识别功能自然结合，同时允许只粘贴为普通文字。

### 13.3 词元识别与视觉状态

- 回载后自动分析可能的主词、前缀和后缀。
- 识别本身不得改变原文。
- 视觉状态：
  - 普通文字：正常显示。
  - 可建立词元：极淡的虚线下划线或等价的低干扰提示。
  - 有歧义或未归组部分：适度区别提示，点击后说明原因。
  - 已建立词元：未激活时仍显示为普通文字，激活后使用相同的三向交互。
- 用户可：
  - 建立单个候选词元。
  - 对选区进行识别及建立。
  - 批量建立所有能够唯一确定的词元。
  - 忽略某个候选。
  - 关闭识别提示。
  - 将已建立词元还原为普通文字。
- 不应将自然语言中碰巧匹配词库的所有词汇强制转换成词元。
- 优先识别符合上下文的键值位置及组合词汇。

### 13.4 已有与新出现的主词、前缀、后缀

- 识别、建立词元、沉淀到词库是三个独立行为。
- 已知完整组合：
  - `高-大型+开发+进行中`。
  - 可以恢复已有主词组及已知前后缀。
- 已知主词、出现新后缀：
  - `高-大型+开发+待复核`。
  - 恢复已知选项和主词，提示「待复核」尚未归组。
- 已知主词、出现新前缀：
  - `加急-小型+测试+已完成`。
  - 根据当前主词组配置识别已知部分，提示未归组部分。
- 出现新主词：
  - `低-中型+归档+待开始`。
  - 可根据已知前后缀提示可能所属的主词组。
  - 由用户确认，不自动强行归类。
- 对新出现的任一部分，允许：
  - 仅本次使用。
  - 指定或加入已有词组。
  - 新建词组并加入。
  - 不建立词元，保留为普通文字。
- 不要求所有组成部分均存在于词库才能建立词元。
- 未归组的修饰词必须保留，不能因切换其他选项而意外丢失。
- 遇到多个可能的主词组、前后缀方向或拆分方式时，提供候选解释，等待用户选择。
- 同名词汇在不同组中出现时，不擅自选取第一个结果。
- 对历史时间戳、数值、包含连接符的词汇等，应考虑合理识别及歧义。
- 例如 `开发+待审核` 与 `高+开发` 都只有一个加号，不能用简单的 split 后固定位置方式判断主词。
- 如果无法安全识别，保留原文，不强制转换。

### 13.5 混合 Markdown 保护

- 回载可能包含：
  - 自然语言注释。
  - Markdown 图片、链接和嵌入。
  - 行内代码、代码块。
  - 反引号、转义符、特殊标点。
  - 原始缩进、空行及各种列表结构。
- 默认保护相关 Markdown 语法内部，不擅自建立词元。
- 图片路径、链接地址中的 `+`、`-`、冒号、括号等不能被误识别为组合词汇。
- 当图片和键值出现在同一行时，应保护图片语法自身，但仍允许识别其外部的键值。
- 不能为了处理图片就简单跳过整个复杂混合内容。
- 不要求回载时加载图片资源或渲染完整 Markdown 预览。
- 不执行 Markdown 中的内容。
- 不自动改写外部文件或图片路径。

### 13.6 无损往返原则

- 导入一段原文后，如果用户未修改内容，则输出应与输入一致。
- 仅建立词元也不得改变原始正文。
- 只修改一个词元时，其余未编辑部分应保持不变。
- 保留标点、空格、缩进、空行、图片路径及未知词汇。
- 不自动执行可能改变回载内容的模板变量或全局转写规则。
- 新生成内容是否执行现有输出转写，应明确区分，并遵守现有 QuickKV 的配置及用户选择。
- 不依赖在 Markdown 中插入隐藏字符、私有标记或 HTML 元数据来实现词元恢复。
- 识别失败可以接受，原文损坏不可接受。

### 13.7 回写原软件

- 用户完成编辑后，可以复制结果或尝试替换原选区。
- 复用现有 QuickKV 的目标窗口、句柄、进程及剪贴板安全机制。
- 只有在能可靠确认目标及原选区仍然适合替换的情况下，才允许自动回写。
- 如果窗口、选区或文档状态无法可靠验证，应降级为复制，由用户主动粘贴。
- 不以发送了粘贴按键作为成功保存的绝对证明。
- 落字失败、目标变化或不支持多行时，必须保留草稿及恢复方式。
- 不擅自实现依赖某个笔记应用专属接口的功能。

## 14. 右键菜单与键盘操作

- 使用上下文相关右键菜单。
- 不同位置提供相应操作：
  - 普通文字或光标位置：插入词元、粘贴并识别、剪切、复制、粘贴、撤销。
  - 普通文字选区：建立词元、选区识别、剪切、复制。
  - 已建立词元：编辑前缀、主词、后缀、转为普通文字、复制、删除。
  - 候选词元：建立、选择所属组、忽略。
  - 大纲节点或分支：新建父级、同级、子级、缩进、移动、折叠、复制分支、删除分支、保存模板及观察框架。
  - 词组：配置、重命名、排序、解除引用。
  - 组内词汇：编辑、说明、移出组。
  - 模块：新建、重命名、复制、排序及删除。
- 右键菜单在鼠标当前位置附近出现。
- 长大纲中的局部操作不应要求返回顶部工具栏。
- 右键点击不能意外破坏已有选区或将插入位置错误移动到其他地方。
- 建议继承现有快捷键及常见大纲操作习惯：
  - Enter：新建同级或按大纲编辑语义换行。
  - Tab：缩进。
  - Shift+Tab：减少缩进。
  - Ctrl+J：检索及插入词汇或建立词元。
  - Ctrl+Enter：整段落字。
  - Ctrl+Z / Ctrl+Y：撤销、重做。
  - Esc：关闭当前浮窗。
- 连续联想候选打开时的 Tab 选词与普通大纲缩进需要根据焦点状态区分。
- 最终快捷键应核对现有软件实际绑定，避免冲突。
- 中文输入法组词期间不应拦截必要的按键。

## 15. Markdown 词库融合

- 新增一个组合输入专用 Markdown 词库，默认名称为 `组合输入.md`。
- 放置于 QuickKV 已有可自动载入的合适词库目录中，具体路径根据本地源码确认。
- 使用现有 QuickKV 支持的普通 Markdown 词条格式。
- 用户创建新词并明确加入词组时，默认写入该词库。
- 已有词汇被加入新组时只建立关联，不重复写入。
- 分类名称、组名及模板名称不自动作为普通词汇写入。
- 临时输入的文字不自动进入词库。
- 组合生成的完整字符串不默认写入词库，避免组合爆炸。
- 动态时间值和动态数值不自动写入词库。
- 从词组移除词汇只解除关联，不等于永久删除原词条。
- 永久删除词条应通过明确的词库管理操作完成，并考虑引用影响。
- 新增、编辑、删除词汇应尽量复用已有 WordManager、WordSource 等能力。
- 不直接改写 其他软件自动生成的词库。
- 对其他只读或外部管理词库，应保留来源信息并避免未经许可的写入。
- 外部词库被移动、删除或变更时，不应导致组合配置及已录入正文被清空。
- 引用暂时失效时保留最后已知文字及关联信息，支持重新关联。
- 新词库写入应具备可靠的原子写入、冲突保护及异常恢复能力。
- 需要核对现有 add_entry 等新增词条路径是否具有与修改、删除相同等级的数据保护。

## 16. 数据模型与持久化原则

- 以下数据应该在逻辑上相互独立：
  - 普通 Markdown 词库。
  - 共享词组及多级分类。
  - 主词组组合配置。
  - 输入模块。
  - 模板及观察框架。
  - 正文、词元实例、选择状态。
  - 草稿及临时回载会话。
  - 软件偏好设置。
- 建议使用 Markdown 词库与版本化结构化配置相结合的方式。
- 不要求所有关系数据都强行储存在 `组合输入.md` 中。
- 词组、词汇引用、模块、模板和词元实例应使用合理的稳定身份标识。
- 不仅依赖可被重命名的显示名称作为唯一标识。
- 已有正文中的实际选择应保留其文字快照，避免共享词组重命名后自动改写历史内容。
- 普通文本与词元元数据应保持一致；处理光标编辑、跨词元选区、粘贴、删除、移动、撤销及重做时不能出现过期范围或数据串联。
- 模板和观察框架可共享定义，不重复维护同一份知识结构。
- 软件关闭、重启和异常退出后的草稿恢复需要可靠。
- 配置版本升级及旧版迁移应有明确机制。
- 普通文本导出始终具有独立使用价值，即使以后不使用 QuickKV，原笔记也可正常阅读和使用。
- 不应把内部数据格式绑定到某一个笔记软件。
- 具体 JSON、SQLite 或其他存储技术由工程方案比较后决定，但必须满足下述安全与备份要求。

## 17. 安全保存、自动备份、手动备份与恢复

- 默认启用本地自动保存。
- 编辑草稿及配置修改后自动保存，合理防抖。
- 默认自动备份保留最近5份有效且内容不同的历史快照。
- 自动备份数量允许用户修改。
- 不在每次点击或选词时立即轮换备份，防止几秒钟内耗尽全部历史版本。
- 建议采用合理的配置变更间隔和启动、退出等保存时机，具体周期由工程方案确定。
- 支持：
  - 创建手动备份。
  - 命名、预览、删除和导出备份。
  - 导入备份。
  - 恢复指定备份。
  - 打开备份目录。
  - 将重要备份固定保留。
- 手动备份及固定保留的备份不参与普通自动轮换。
- 导入、恢复、重大批量删除、数据格式迁移等高风险操作之前，先创建保护快照。
- 自动备份应至少包含相互匹配的组合配置与 `组合输入.md`。
- 外部词库默认仅保存必要引用，不擅自覆盖外部文件；若恢复依赖外部文件缺失，应明确提示。
- 每份快照具有格式版本、创建时间、必要的完整性校验及引用信息。
- 新备份完整写入并校验成功后，才能清理旧的自动备份。
- 恢复前应：
  - 预览恢复内容与影响范围。
  - 校验数据结构、格式版本及引用关系。
  - 保护当前有效数据。
- 恢复过程中不能产生一半配置为新、一半词库为旧的不一致状态。
- 采用可靠的事务或等效的可恢复提交机制处理跨文件保存与恢复。
- 写入失败时保留原有有效数据。
- 配置加载失败时，不得自动用空白配置覆盖旧数据。
- 备份损坏时应允许选择其他有效快照。
- 草稿默认进行本地恢复保护。
- 是否纳入长期配置备份由用户选择。
- 恢复配置不能静默丢弃当前未完成草稿。
- 不默认记录外部软件的剪贴板历史。
- 不自动上传词库、草稿或备份至云端。
- 本机备份不能防止硬盘整体损坏，因此必须支持独立导出及迁移。
- 需结合 QuickKV 已有配置路径、安全写入、冲突备份及数据安全测试，不另建一套互相冲突的机制。

## 18. 典型使用场景

### 18.1 项目任务管理

```markdown
- 导航改版，时间：20310408091753
  - 任务：高-大型+开发+进行中、开发+待审核
  - 任务目标：更新菜单导航
  - 依赖：设计稿已准备
    - 负责人：设计组
    - 完成比例：75%
  - 结果：
```

- 用户通过词元选择快速修改时间、任务状态和已观察到的进度。
- 同一个任务类型在不同位置的前后缀相互独立。
- 允许随时增加同一行的键值组及自然语言。
- 可以复制或调用同一框架创建不同任务节点。
- 不要求所有观察维度必须填写。
- 可以快速查看遗漏的观察维度。

### 18.2 日常事务管理

```markdown
- 社区活动准备
  - 物料：海报，已交给志愿者
    - 送达：公共阅览室
    - 检查：验收通过⭐
  - 物料：桌牌，数量：12
    - 送达：活动室
```

- 尚未稳定的记录结构允许自由新增和修改。
- 同名事件独立存储与计算，调整顺序后也不串值。

### 18.3 混合 Markdown 回载

```markdown
- 活动页面验收
  - 任务：高-大型+开发+待复核、低-小型+归档+待开始，照片由组员整理
  - 资料：草图及检查记录
    - ![页面示意](images/layout+notes-v2.png)，进度：中+审核、75%
    - 用 ``id = "layout-v2+draft"`` 标记附件
  - 结果：待确认
```

- 图片、行内代码和自然语言保持不变。
- 同一行受保护语法之外的键值继续识别。
- 已知词汇提供识别提示。
- 新主词、新前缀和新后缀可以暂时使用或明确加入词组。
- 用户未修改的任何内容应在回写后保持一致。

## 19. 质量要求及开发优先级

- 首要目标是用户实际录入效率、低干扰和长期可靠性，不是功能数量。
- 核心技术闸门：
  - 原生 Qt 编辑器与中文输入法。
  - 普通文本、组合词元及自然光标共存。
  - 大纲操作与撤销、重做。
  - 浮窗定位、焦点、悬浮和拖动。
  - 回载无损往返。
  - 现有 QuickKV 词库、搜索和落字机制复用。
  - 数据安全及草稿恢复。
- 建议阶段：
  - 阶段0：源码审查、风险分析、技术路线验证。
  - 阶段1：统一编辑器、词元模型、大纲、基础浮窗及模式融合。
  - 阶段2：词组、多级分类、前后缀配置、检索引用、动态组、排序、多模块及安全持久化。
  - 阶段3：完整回载、模板、观察维度、词汇标准、备份与恢复。
  - 阶段4：真实 Windows 环境下的功能、兼容性、性能、数据安全及回归测试。
- 可以根据技术依赖调整阶段顺序，但不能把后续功能从最终规格中删除。
- 数据安全基础及回载所需的数据模型应从第一阶段考虑，不能等到最后才处理。
- 各阶段应提交明确的变更范围、测试结果、未解决问题及后续建议。
- 不擅自修改关联的外部项目。
- 暂时不开发 AI 自动代替用户作出专业判断、自动执行外部业务操作或复杂知识图谱等无关功能。
- 所有自动提示都应辅助用户判断，而不是替用户制造未经观察的数据。

## 20. 最终验收目标

- 选择比重复打字更快速。
- 界面平时如自然大纲一样轻盈。
- 不受固定表单和预设结构限制。
- 主词组、前后缀及词元配置自然复用。
- 可以方便维护词汇、分类和判断标准。
- 回载、编辑、回写形成可靠的双向工作流。
- 动态时间戳在选择后永久固化。
- 数据可安全保存、备份、恢复、导出和迁移。
- 不破坏原有 QuickKV 的任何已确认功能。
- 用户在真实项目和日常记录中愿意长期使用。


## 第四轮生效规则

组合输入公开界面称结构化对象为「组合词」，称可复用分支内容为「片段」。模块快切与完整管理分为两个入口。空查询支持按模块词组直接选词。直接输入的主词可暂不归组；配置前后缀时再明确绑定。疑似组合回载允许用户确认角色与归组，确认提交同时保存专用词库、关联与草稿。详见 [第四轮修订](第四轮UI修订.md)。


## 第五轮生效规则

三向非空查询使用全局检索。默认展示范围和收藏不限制匹配，关联由用户确认。回载按正文边界独立发现候选，未发生实际变化的组合词保留身份及原文。详见 [第五轮修订](第五轮核心修订.md)。
