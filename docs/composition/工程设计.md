# QuickKV 组合输入工程设计

**阶段 0 已审核 · 2026-11-25**

在现有 QuickKV 弹窗内增加「组合输入」。正文采用原生 Qt 自由编辑，词元、观察维度和大纲操作依附于同一份正文。共享配置及草稿使用版本化 SQLite，专用 Markdown 词库继续由 QuickKV 自动加载。外部回载沿用同一编辑器，只有能验证原选区且能安全执行替换的目标才启用自动回写。

## 1. 源码现状与改动入口

当前本地 `main` 为 `b0dd37f`，代码版本为 1.3.10。源码运行时数据位于 `src/` 下，打包后位于 EXE 同级目录。下列文件是后续实施入口。

| 入口 | 当前行为 | 组合输入接入点 |
| --- | --- | --- |
| `src/ui/search_popup.py` | 「连续联想」按钮的选中态决定两种模式，窗口大小、聚焦、搜索刷新和 Esc 走二选一分支 | 引入 `SEARCH / CONTINUOUS / COMPOSITION` 显式状态。标题栏按图 1 增加按钮，选中态从模式派生，原按钮保留再次点击回搜索语义 |
| `src/main_controller.py`、`src/services/hotkey_manager.py`、`src/services/shortcut_listener.py` | 热键唤窗前捕获外部句柄。快捷码识别和延迟删码主要针对连续联想做保护。退出、自动重启也直接检查连续联想草稿 | 区分模式、草稿会话与外部目标。保护两种草稿编辑及其子浮层，覆盖延迟删码的实际执行点。退出和自动重启先处理待写草稿 |

| `src/core/word_manager.py`、`src/core/template_renderer.py` | `find_matches(..., candidates=...)` 可限定候选集合。现有索引和排名支持拼音、首字母、别名等。模板支持时间及格式化 | 共用词库索引和检索。组合词组先按模块或当前角色缩小范围。时间组与模板共享时间格式化能力，选取时间值时一次性求值 |

模式切换仅改变页面和焦点。每个模式记忆自身尺寸，组合输入先按可用屏幕边界布置，混合 DPI 或跨屏时重算位置。普通搜索继续保留原结果选择和唤窗行为。全局 `Ctrl+空格` 保持唤窗用途。回载热键独立可配置并预检冲突，初期可通过菜单入口验证。组合输入按需初始化，存储故障应只影响组合输入。持久化记录涵盖组合输入草稿和回载会话，连续联想沿用自己的草稿行为。

## 2. 正文、词元与编辑事务

### 编辑器选型

| 方案 | 判断 |
| --- | --- |
| `QPlainTextEdit`、原生文本及自定义格式属性 | 首选。保留中文输入法、自然光标、换行、选区和原生撤销。用额外选区、可见块定位和子浮层显示提示 |
| `QTextEdit` 内联对象 | 对富文本对象合适。词元替换成对象会引入对象占位、边界光标和纯文本导出问题，尤其影响词内改字与无损剪贴 |
| 自绘编辑器或树表格单元格 | 对固定录入表格合适。自由段落、跨节点选择、长文布局、中文预编辑和撤销均需重新处理 |

`QTextDocument` 是编辑会话的实时投影。普通字符继续由 Qt 排版，词元格式属性仅携带实例 ID。编号、折叠和观察标记使用块定位和边栏或浮层。存档采用原文和验证过的结构记录，范围用统一的原文偏移表示。Qt 的 UTF-16 位置与 Python 字符索引在适配层转换，识别结果必须带文档修订号、原始范围与预期字面。会话重建时逐项验证范围、快照和身份，异常标记单独报告，原文可独立打开和导出。 [Qt 编辑器](https://doc.qt.io/qt-6/qplaintextedit.html) · [Qt 光标与编辑块](https://doc.qt.io/qt-6/qtextcursor.html)

`toPlainText()` 会改写部分 Unicode 空格和分隔符，`toRawText()` 也无法恢复 Qt 合并的 CRLF 与 CR。导入先保存原始字符串，根据 Qt 实际投影建立偏移映射，逐处记录有损归一化的原始片段。分隔符落在明确的行边界，拆行、合行、移动分支按编辑事务更新边界归属。未改区域按原始片段拼回，新建行使用会话约定的换行。混合换行、末尾空行、NBSP、U+2028/U+2029、制表符和代理对都纳入验证。内部验收以收到的字符串逐字符一致为准，另测操作系统剪贴板与目标应用自身的换行转换。 [Qt 文档的纯文本与原始文本](https://doc.qt.io/qt-6/qtextdocument.html)

词元格式、节点身份与受影响的原文映射必须共享同一次可撤销操作。程序发起的命令用 `QTextCursor.beginEditBlock()` 组合。原生打字、IME 提交、粘贴和拖放都要验证标记变化能否可靠地并入原生撤销。边界插字写成普通格式，手动修改词元内部或跨过部分词元时，解除受损实例的关联并保留改后文字。回退一次同时还原正文和原词元。词元的程序化替换用同一事务写入新正文及新快照。输入法预编辑只更新交互状态，提交后再处理标记。原型若无法让原生编辑和元数据稳定共享撤销，实施闸门应改用统一的编辑事务及结构记录，再验证 Qt 原生输入路径和性能。单独维护互不协调的两套撤销栈会导致旧范围复活。

节点使用稳定 ID。编辑同一节点保留 ID，拆分分配新 ID，合并由保留节点继承，移动保留，复制和模板实例化重新分配。Qt 新段可能继承原块的格式，因此必须在编辑边界校验重复 ID。普通 Markdown 解析与大纲视图可描述列表、文本和混合片段。父级、同级、子级、缩进及反缩进、折叠、移动、复制、删除均只作用于明确分支，连同附属正文和词元一起移动。导入普通段落、编号、引号、围栏及特殊缩进时保留原字面，用户明确执行结构操作才改变相应范围。跨折叠区的选区操作仍必须覆盖实际选区，且可撤销。

### 词元实例与浮窗

词元保存主词组 ID、主词快照、两侧有序选择、各项词组引用和文字快照、未归组部分、实际输出字面。结构未被主动编辑时保留原字面。新建或有意重组时按 `前缀-前缀+主词+后缀-后缀` 输出，省略空侧与连接符。前后缀里的某项变更只替换该项，未归组选项保持原样。同组换主词保留修饰词。浏览其他组只预览，提交跨组变更时说明哪些修饰词将丢失，并支持单步撤销。组内排序、默认引用顺序及旧实例输出顺序各自保存，分享的配置变动只影响之后的选择。日常面板拖动引用顺序时明确当前实例与共享配置的作用范围，配置更新和正文重排均支持撤销。

按图 2 到图 5，实现锚定当前词元的前缀、主词、后缀三个入口。平时正文只有普通文字。打开时在文字附近显示入口与面板，按屏幕可用区域优先下方，空间不足向上，必要时限制高度并内部滚动，实时结果留在底部。锚点在滚动、窗口拖动、尺寸和 DPI 变化时重算。面板点击选项立即生效，已选项可取消。主词面板支持在组内和跨组检索、选组、临时主词。组数超过五个时先展示前五组，附加组支持悬浮立即展开，也支持点击，打开后保持展开直到离开面板会话。

悬浮响应默认关闭并记忆设置。打开后，文字区到浮层的路径保留当前目标，点击进入、配置或拖动时锁住当前浮层。输入法组词、文字选区、拖放以及右键菜单期间暂停自动悬浮。Esc 在指针离开前抑制同一词元重开。先让输入法处理预编辑按键，再处理浮层及候选键，最后由编辑器解释 Tab / Shift+Tab、Enter、Ctrl+J、Ctrl+Enter 和 Esc。Ctrl+Z / Ctrl+Y 作用于当前编辑上下文。右键按位置解析普通文字、选区、词元、候选或分支，保留右键前的有效选区。分支保存模板、观察框架和编辑操作在当前位置可用。按图 1 和图 6 验收主界面工具区域、模块检索、局部工具和右键交互，Markdown 预览默认收起，可直接显示安全的纯文本输出。

## 3. 共享词组与独立输入模块

| 对象 | 持久化内容与边界 |
| --- | --- |
| 词组与分类 | 稳定 ID、名称、类型、排序和任意层级分类。类别负责导航，选中词汇才参与输出。分类树验证同组父子关系、防环和同级拖动 |
| 词汇引用 | 可链接现有 Markdown 来源，一个词可入多个组。记录来源标识、相对路径或外部路径、词条指纹、最后已知文本和辅助定位。现有 Markdown 没有稳定词条 ID，多重匹配置为待重连 |
| 主词组及规则 | 主词组引用共享词组。每个角色有独立、有序的组引用，防止同侧误重复。每个修饰组选零或一个值，可有很多组。同一词出现在多个组时显式选组 |
| 词汇说明 | 定义、判断标准、说明、反例作为可选配置，按需查看。历史选择的文本快照保持原样 |
| 输入模块 | 稳定 ID、名称和顺序、局部快捷入口、词组范围、模板、观察框架及当前草稿身份。保存会话光标、选区与必要折叠状态，记忆最后使用模块 |
| 草稿与回载 | 模块草稿和回载会话各有 ID 和修订号。回载继承模块配置并持久化可恢复正文，结束或切换可返回原草稿。重启后外部目标需重新建立 |
| 应用偏好 | 新功能相关悬浮、识别、备份等偏好随组合输入配置版本管理。既有 QuickKV 通用窗口、字体、主题、热键和词库偏好沿用现有设置服务 |

配置浮窗左侧为当前引用组，右侧编辑当前组或分类。引用时可搜索和浏览共享组。组/模块支持新增、改名、复制、排序、删除；组的共享改动、解除当前引用、移除某个词与永久删除源词条是各自明确的操作。复制模块时新建模块身份，草稿是否带值由用户选择，引用仍可共享。删除有草稿的模块前建立保护快照并说明恢复入口。配置和日常面板支持拖动，用位移阈值区分点击和排序，拖动期间显示落点并暂停悬浮。新建普通词时复用加载器可正确往返的格式，已有词只建立引用。组名、分类、临时词、生成的组合结果及动态值均留在各自数据模型。

数值组用十进制定点语义保存，校验范围、精度、步长和单位，常用值可点选，也可手工输入。空值保持未选择。时间戳组初始化规格中的十种格式，14 位、4 位、8 位排在前面，可作为主词或任意侧修饰组。面板打开时按本机时间刷新，选项显示实际值，格式名放在提示里。点击时取同一个当前时间重新计算选项并固化；历史编辑、导出和恢复始终使用已保存快照。动态组与显式模板变量共享时间格式化，不进入普通词库。按图 3 到图 6 验收组共享、实例独立、动态值与模块切换。

## 4. 无损回载、识别与回写

### 导入与识别

普通粘贴或「粘贴并识别」在当前文档执行，也可把内容打开为独立回载会话。外部选中回载在 QuickKV 抢焦点前尝试读取明确的外部选区。有可靠 UI Automation 文本提供器时，先读取选区和来源信息。否则可在用户触发的专用操作中请求目标复制，检查目标、序列号确实变化及获得文本，失败时保留原草稿。若使用剪贴板走选区采集，纳入 QuickKV 的剪贴板事件来源识别，避免这次主动采集顺便进入历史。只有确认剪贴板仍是本次操作产生的版本时才可能恢复原内容，遇到第三方更新立即放弃恢复。图 8 对应的识别提示可关闭，右键提供建立、候选解释和忽略。

识别先建立 Markdown 源位置保护区，再扫描保护区之外的原文。解析器用于定位，导出直接取编辑后的原文。覆盖图片、链接、引用定义、行内代码、代码块、自动链接、转义和常见嵌入，源位置能力不足时标记相应局部为保留区。对 `![页面示意](images/layout+notes-v2.png)，进度：中+审核、75%`，前半句保留，后半句照常识别。原文分析可按修订号排队或增量运行，结果回填前校验受影响范围，避免迟到结果套在新文字上。预览采用文本显示或限定渲染能力，图片资源及外部链接在识别时均无需访问。 [CommonMark 块和行内语法](https://spec.commonmark.org/0.31.2/)

优先从键、值和组合边界生成候选，保护自然语句、时间冒号、小数点以及一行多键值。按当前场景用主词、词组顺序、词汇前缀与后缀生成有限候选。先匹配完整词汇，再尝试边界拆分，允许连接符是词汇的一部分。比如 `高+开发` 和 `开发+待审核` 都按组证据推断，`高-大型+开发+待复核` 标出未归组的后缀，`低-中型+归档+待开始` 可给出主词组建议。有多个解释的范围显示原因并由用户选。按当前格式判定历史时间和数值，只取文本快照。限制长片段与候选数量，无法安全解释时原样保留。

识别只显示提示，建立词元只附加结构，明确选择加入词库才持久化词汇。单个、选区和批量建立共用同一入口，批量只处理确定且无重叠的候选。已知与未知可共存，任一未知部分均支持临时使用、归入已有组、新建组后加入或放弃建立并保留原文。回载数据及新建组合正文均以当前显示文本为复制基准。动态变量只在用户显式调用模板等生成动作时解析。组合输入的输出转写建议作为新建会话的显式选项，默认保留现有字面。含原文的回载会话默认精确输出，仅用户主动编辑的范围发生改变。连续联想和普通搜索沿用现在的模板、转写与输出设置。

### 外部回写

`HWND + PID` 只证明窗口与进程，无法区分同一窗口的不同文档、控件或选区。外部回载能力验证应拿到文档和焦点控件身份、明确的单选区、位置或端点及原文，并在实际替换前重验。重复出现的相同文字也需要端点或等价位置证据。首选具备经实证的条件式替换能力的 Windows 通用适配路径。UIA 的文本查询可用于采集和比对；检查后发送全局粘贴有时间差，窗口标题、选区内容相等及发送进程返回码都不足以视为目标编辑成功。目标提供者不支持可靠替换、文档变更、选区恢复失败或目标不支持多行时，直接复制结果供用户手动粘贴。各应用均走相同能力判断。 [Windows UI Automation 文本模式](https://learn.microsoft.com/windows/win32/api/uiautomationclient/nn-uiautomationclient-iuiautomationtextpattern) · [Windows 输入派发返回语义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

普通新稿「落字到…」是主动将正文插入既有目标，沿用焦点稳定、剪贴板对账及多行限制。派发结果区分「已复制」「已发送」「确认已替换」，成功发送按键后仍保留草稿或已发送快照，失败时原会话和目标信息留在编辑器里。回载会话的目标上下文在本次运行内有效，跨重启失效。验证常用笔记应用和至少一种原生编辑控件是否具备安全替换能力，同时覆盖同窗换文档、同字串错选区、选区消失、焦点跳转、剪贴板竞争及只读目标。

## 5. 模板与观察维度

模板从选中节点及分支保存，复用大纲、普通文字段及词元结构。保存时明示全部保留、清空需重新观察的值或逐项保留，调用和复制时重新分配节点、词元身份。清空后的词元插槽保存角色与词组关联，以可点击提示显示，并从导出文本中跳过尚未填写的占位。只对模板创建时明确标记的空占位应用省略规则。有正文或承载有效子级的父节点继续输出，回载原本就有的空行和空键继续保留。支持模板检索、编辑、复制、排序、删除及显式求值的动态变量。当前真实分支复制时提示哪些实际观察会被带到下一次记录。

观察框架可以从模板提取或独立编辑，分析根节点绑定框架 ID，维度用键名或父子路径，支持按需明确关联到输入位置。按根节点范围向下读取实际正文，遇到其他已绑定框架的子分析即停止对该分支的统计，按路径验证非空值，允许同名任务或重复事务并存。遇到同层多个符合位置时，在当前根内显示候选以避免跳错。主动设置的「无法判断」「不适用」随该分析节点存储，不写入笔记；正文有实际值时按已记录，删除后重新计算。计数建议用已记录 / 适用维度，无法判断仍属于适用维度并单独显示，不适用从分母扣除；全不适用时显示对应状态。允许全局、模块或节点关闭。图 7 的淡色指标锚定相应父节点，列表点击时跳到已有位置或按正确路径创建输入位，未补内容保持待记录。

## 6. 保存、备份与恢复

### 存储选择

单一 JSON 易于审阅，草稿频繁保存时需要重写整个文件，并自行实现版本、约束及高频与低频写入的协调。选择 Python 标准库 SQLite 作为本地结构化数据源，草稿按会话写入、配置用稳定 ID 与外键，草稿正文和结构以同一修订提交。可用普通 Markdown 导出草稿，备份包保留可迁移的结构关系和独立的 MD 文件。首版为单写入者，优先采用本地回滚日志和可靠同步，按实测决定是否有并发读取需求再启用 WAL。Python 3.13.7 的本地环境中 SQLite 为 3.50.4，打包验证需单独确认依赖和运行版本。 [SQLite 的日志方案](https://sqlite.org/wal.html) · [SQLite 同步级别](https://sqlite.org/pragma.html#pragma_synchronous)

建议文件位置为 `用户数据/组合输入.sqlite3`、`用户数据/组合输入备份/` 及 `MD词库-需自动载入的请放入/组合输入.md`。新功能首次使用时安全初始化，若同名 MD 已存在就读取并预览冲突，保护已有内容。MD 使用普通 `- 词条`，现有搜索可读取。专用文件的新增、编辑、删除及从普通搜索写入都通过同一安全入口。外部管理路径只读引用，缺失时显示最后已知文字及来源，恢复可重新关联。词条文本、路径与引用不写入调试日志。识别缓存和搜索索引可重建。草稿默认仅本地恢复，长期备份是否包含草稿由用户选择。

### 跨 SQLite 和 MD 的可恢复提交

SQLite 事务只能覆盖数据库。专用 MD 的新增、恢复及任何同时修改共享引用的操作，使用持久化事务意图和同目录原子替换。原有 `WordSource` 的 Windows 冲突保留机制是替换环节的基础，还需覆盖不存在文件的安全创建、追加原字节、明确冲突结果以及供恢复保留的旧版本。单进程锁协调 QuickKV 自身入口。外部编辑器可以并发写 MD，因此观察到不同的外部版本时按冲突处理。

1. 验证计划变更、旧 MD 与新 MD 的字节和哈希、预期数据库修订。恢复和批量操作先写出并验证保护快照。用 SQLite 完整提交事务意图，保存恢复所需的前像、后像或经校验的独立恢复材料。
2. 按预期版本原子替换 MD，重新读取校验落地结果。现有 Windows 替换在碰到执行瞬间竞争时可保留对方版本。本文方案要求冲突结果进入事务恢复状态，避免把布尔失败误当成未曾写盘。
3. 同一 SQLite 事务提交新配置、去除待处理状态并记下提交修订。词库监听和 UI 在本进程内围绕提交边界暂停发布，完成后合并刷新。数据库修订失败时保留恢复材料。
4. 启动时先恢复待处理事务，再开放组合输入及加载对应 MD。若数据库仍是旧版且 MD 是旧哈希，安全撤销未落地事务。若 MD 是目标新哈希、数据库仍在预期修订，按完整意图前滚。若遇到第三方版本或对应材料缺失，保留可恢复材料并提供明确的冲突处理入口。允许正常使用其他模式，对有冲突的专用词库暂缓发布；普通配置和外部词库可照常工作。

进程内的读者只看到一致提交。可独立读取 Markdown 的第三方程序可能读到文件替换与 SQLite 提交之间的短暂中间状态，应用启动后按日志恢复。后续外部编辑属于新的版本，按引用失效或重连规则处理。验证要在每个持久化步骤后杀进程，另测 MD 外部改动、磁盘满、权限错误、文件锁、哈希不一致、SQLite 损坏和损坏备份。比较重启后的正文、词库字节、关系及可恢复材料。

### 自动保存与备份轮换

草稿建议初始防抖 350 ms、持续输入最长 2 s 写入一次，实际以 Windows 长文测试调优。按会话和修订串行落盘，旧任务结果不得覆盖新稿。模块切换、回载结束、正常退出和应用自动重启前集中确认未写修订。保存失败显示未保存并保留内存稿，允许重试或复制出来。崩溃恢复以磁盘上最后一次已提交修订为准，验收实际损失窗口。数据库加载失败进入组合输入恢复状态，保留原文件以便导出或选择快照。

备份使用 SQLite Backup API 生成一致数据库快照，在写入协调期间获取同一已提交版本的 MD 字节。备份包含格式与模式版本、创建时间、范围、修订、SHA-256、外部引用摘要与文件清单。备份前后比对 MD 版本，竞争时延期。配置、专用 MD 和组合输入偏好进入默认备份，草稿可选，通用设置仍由 QuickKV 现有配置管理。备份按逻辑内容去重，忽略创建时间和数据库页布局。初始建议配置实际变化后以约 15 分钟最小间隔自动备份，在启动发现未备份变化或退出时尝试补齐，同时守住轮换间隔。默认只轮换最近 5 份内容不同且验证成功的自动备份，数量可调。手动、固定、保护快照独立保留。 [SQLite Backup API](https://sqlite.org/backup.html)

支持手动命名、列表、预览、删除、固定、打开目录及单文件导出/导入。导入预览清单和缺失外部引用，校验文件大小、哈希、版本、数据库完整性、外键、业务不变量及安全文件路径，再持久化保护快照、按统一流程恢复。恢复默认保留本机当前草稿及其原文、词元快照；受影响的旧组 ID 标记为待重连，草稿仍可打开，包含草稿的快照另行选择导入。版本升级与格式迁移也先验证保护快照，在事务内迁移结构并保留支持范围说明。图 9 的关键验收是恢复出的配置和 MD 成对，以及备份故障或跨文件中断后可再次恢复。

## 8. 本轮验证

- 在项目虚拟环境的 PySide6 6.10.2 上执行隔离的 Qt 小实验。对一段测试文字附自定义格式后正文保持一致，原生 undo/redo 会撤销和恢复格式。普通打字在词元右边界继承词元格式，模拟 IME 往词内提交也继承格式。新段继承块格式中的节点 ID。Qt 将混合 CRLF / CR / LF 投影到段落字符，`toPlainText()` 还会把 NBSP 变为空格。emoji 后字符的 Qt 偏移与 Python 索引不同。
- 现有全量测试共 77 项。首次运行中，第二实例立即退出的 Qt 激活用例失败，子进程报告已通知，主实例未收到预期的激活。该用例单独复跑通过，第二次全量 77 项通过。保留此间歇现象作为后续模式切换与热键回归基线。
- Qt 小实验使用 offscreen 及合成输入法事件。真实 Windows 输入法、窗口浮层、目标回写、跨文件中断恢复及实际录入效率仍要在实施阶段验证。


## 9. 实施差异

- 编辑器继续采用原生 Qt。技术验证发现字符格式可随普通输入继承，段落格式也会复制旧身份。实际实现用同一个编辑事务管理正文、词元、节点、原始分隔符和选区。Qt 负责渲染、光标、选择和输入法提交，应用统一负责撤销和重做。
- SQLite 维持单写入者。草稿和配置分别保存，专用 MD 复用 Windows 原子替换原语。跨文件写入以持久化前像与后像对账，启动时先恢复再加载专用词库。在无法辨别的第三方版本出现时保留数据和事务意图，并提供明确处理入口。
- 长期可迁移备份使用版本化 ZIP，包含同一受协调读事务取出的结构数据、专用 Markdown 和 SHA-256 清单。数据库表及日志留作运行期实现。这种备份便于版本间验证和选择性恢复草稿。
- Markdown 识别使用保守的源区间扫描，保留原文本及受保护内容。长草稿的识别在单线程后台执行，只有当前修订结果可以进入编辑器，候选提示按可见区绘制。
- 外部选区采集复用目标窗口守卫和剪贴板序列号，额外验证剪贴板所有者进程。回载输出统一使用复制降级。受支持的通用条件式替换能力仍待建立并实测。
