# QuickKV 组合输入本地交付记录

2026-11-25 · Windows 开发测试包

本地实现已覆盖三种输入模式、自由大纲、三向词元、词组及多级分类、输入模块、回载识别、分支模板、观察维度和备份恢复。回载输出目前提供复制降级。现有外部目标窗口守卫无法证明同一窗口里的原文档和原选区仍可安全替换，相关验收保留为未完成项。

## 操作入口

- 在 QuickKV 标题栏选择「组合输入」。左侧选择模块、模板和回载，正文工具栏操作同级、子级、缩进和撤销。使用 Ctrl+J 或「＋词元」打开词元检索，使用右键操作选区或分支。
- 点击已有词元打开前缀、主词和后缀入口。按需开启悬浮响应，配置词组，维护分类、说明和关联顺序。可在「更多」开启正文连续联想。
- 「回载」支持从外部选区或剪贴板打开同一编辑器中的独立草稿。确定候选可以批量建立，未知或歧义候选可按解释处理。「替换或复制」将结果复制到剪贴板。
- 用分支右键保存模板或设置观察框架。更多菜单提供模块、共享词组、手动备份、导入、恢复和保留配置。默认长期备份保留 5 份有效自动快照，草稿加入长期备份由用户选择。
- 运行完整本地测试包目录中的 QuickKV.exe。它使用该目录下的词库与用户数据。验收前可关闭正在运行的正式版，避免两个实例竞争同一个全局热键。

## 实现位置

| 位置 | 职责 |
| --- | --- |
| `src/ui/search_popup.py`、`src/main_controller.py` | 三模式、热键、剪贴板、现有落字、安全目标守卫及生命周期 |
| `src/ui/composition_editor.py`、`src/ui/composition_workspace.py` | 原生编辑、统一撤销、独立草稿、布局、右键、预览和操作入口 |
| `src/ui/composition_panel.py`、`src/ui/composition_workflows.py` | 三向浮窗、词组与模块、回载、候选、模板、观察框架及备份界面 |
| `src/core/composition/` | 正文与元数据、规则、原位置识别、SQLite 跨文件恢复、可迁移备份 |
| `src/core/continuous_matcher.py`、`src/core/word_source.py` | 复用连续联想匹配；专用 Markdown 接入恢复式写入 |
| `src/services/composition_capture.py` | 用户发起的选区采集、前台及剪贴板来源检测 |

## 验证结果

- 项目虚拟环境全量 **103 项通过**，包含 77 项原测试和 26 项组合输入新增测试。原始基线曾观察到第二实例立即退出时，主应用没有收到激活。该用例单独复跑和后续全量通过，偶发问题的原因仍未定位。
- 使用临时目录及虚构数据验证原文及结构往返、选区复制、Unicode 与混合换行、词元边界撤销、节点身份、模式和模块切换、时间固化、受保护 Markdown、备份轮换、损坏备份和恢复保留草稿。杀子进程及 Windows 文件替换试验覆盖提交前后和外部写入竞争。
- Windows Qt 原生后端渲染检查了标题栏、正文、词元入口、前缀和配置布局。自动 IME 测试使用 Qt 合成事件。视觉检查和自动事件不能证明真实输入法或手势体验。
- 同一虚构数据下，5,001 行大纲前部连续 20 键从约 390 ms 降至 156 ms，配合 25,000 个候选词的整篇识别从约 784 ms 降至 91 ms。数字为隔离测量，真实用户录入速度仍需计时对比。
- PyInstaller 本地打包成功，使用独立副本验证便携启动、通用初始化、依赖带齐及第二实例进程快速退出。构建工具曾提示可选时区数据隐藏导入缺失，便携启动和本地时间戳自动用例通过。
