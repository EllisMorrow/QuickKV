# QuickKV 组合输入隐私与发布审查

开发、测试、截图和演示使用独立构造的虚构项目、阅读和日常事务数据。公开初始化提供少量独立编写的常用回复和通用组合输入预设。预设仅用于新目录，发布包内不附带运行产生的数据库或词库。用户可以加入自己的词组、模板和草稿，这些内容由本地数据和备份机制管理。测试使用临时目录与独立剪贴板输入，故障注入以假数据为输入。

## 持久化边界

| 数据 | 处理 |
| --- | --- |
| 产品规格和九项交互规范 | 公开文档保留功能、数据契约、交互和验收，示例采用虚构资料 |
| 原始附件及私人参考图 | 本机忽略目录，保留原文件，公开目录只保存通用行为说明 |
| 专用 Markdown、数据库、草稿、用户偏好及备份 | 进入现有用户数据或词库目录，源码运行布局和便携布局均检查忽略规则 |
| 自动化测试、日志及构建 | 使用独立目录。审查新增报错内容，备份格式、截图和演示也采用通用数据 |
| 打包资源 | PyInstaller 的数据文件使用显式清单。构建产物需检查内部路径及内容，发布不直接复用日常运行目录 |

## 阶段审查

阶段 0.1 之前确认原始素材隔离、规格章节和验收项完整、公开初始化和测试样例去敏化。阶段 1 至 3 每阶段审查代码、配置、测试、文档和新生成物。阶段 4 在干净的独立运行目录检查数据生成、打包文件和功能独立性。

用户实际验收后，任何 push 或正式发布之前再次审查全部拟公开代码、资源、词库、示例、文档、测试、运行产物、图片和发布附件。检查 Git 索引、暂存区、拟公开 diff 和将推送的提交范围。专项报告记录范围、发现、整改、证据和剩余风险。发现既有提交含私人资料时记录文件和影响提交范围，在授权前保持历史和用户数据原状。
